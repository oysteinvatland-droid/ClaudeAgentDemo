## Agent Architecture

```
COORDINATOR AGENT
  Role: Requirement analysis & task specification
  Tools: Read, Glob, Grep (read-only)
  Output: Structured project spec with API decisions
       ↓
DEVELOPER AGENT
  Role: Implementation analysis & decision documentation
  Tools: Read, Glob, Grep (read-only)
  Input: Coordinator's spec + actual source files
  Output: Technical documentation of implementation choices
       ↓
TEST AGENT
  Role: Validation, edge-case analysis, improvement suggestions
  Tools: Read, Glob, Grep (read-only)
  Input: Developer's analysis + actual source files
  Output: Test report with production-readiness assessment
```

## How to Run the Agents

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...
python agents/orchestrate.py
```

Each agent uses the [Claude Agent SDK](https://github.com/anthropics/claude-agent-sdk-python)
with `query()` and built-in file tools (`Read`, `Glob`, `Grep`).
The agents run in sequence, with each receiving the previous agent's
output as context in their prompt — simulating real team communication.

## Learning Outcomes

This project demonstrates how role-based AI agents can work like a development team:

| Agent | Mirrors | How |
|-------|---------|-----|
| Coordinator | Tech Lead | Breaks requirements into specs, makes architectural decisions |
| Developer | Senior Engineer | Implements features, documents technical choices |
| Test Agent | QA Engineer | Reviews for correctness, identifies failure modes |

The agents **build on each other** — the developer reads the coordinator's spec,
the tester reads the developer's analysis. This is the same way real teams work.

### Key Claude Agent SDK Patterns Used

1. **Distinct system prompts** — each agent has a persona and responsibility boundary
2. **Context passing** — previous agent output is injected into the next agent's prompt
3. **Constrained tools** — all agents are read-only (`Read`, `Glob`, `Grep`)
   to prevent unintended modifications during analysis
4. **Sequential orchestration** — `await` each agent before starting the next
5. **Result capture** — `ResultMessage` gives the final agent output as a string
